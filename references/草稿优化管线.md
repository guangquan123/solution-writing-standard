# 模式 C 执行细则：草稿优化管线

> 本文件是 SKILL.md **模式 C（草稿优化）**的执行细则。触发条件：已有稿、无评审意见、目标是整体优化到可交付。硬约束编号以 SKILL.md 统一编号为准，本文引用处已对齐。

## 输入要求（材料型，三档处理）

| 档位 | 条件 | 行为 |
|---|---|---|
| 材料齐全 | 方案稿（md/txt/docx）＋语料库目录都在 | 走主工作流：⓪ 诊断 → 四轮管线 |
| 缺一部分 | 有稿缺语料，或缺页数预算/行业背景等参数 | 输出缺失项清单（缺什么、为什么要、建议从哪获取），停止扫描与替换并向用户索取；缺参数时只跳过依赖该参数的层并明示，不做推断 |
| 只有话术 | 未给稿（如只说"帮我优化方案"） | 输出必需输入清单（①方案稿文本或路径 ②语料目录 ③可选：页数预算、行业背景、限定只跑某轮），停止，不动笔 |

语料优先级：A 委托方制度/管理办法 ＞ B 招标/投标文件 ＞ C 国标行标 ＞ D 行业方案。内容红线：见硬约束 1（禁虚构）与 2（不自造词），任何档位不得违反。

## ⓪ 接稿诊断（必做，输出轮次计划）

读完草稿，出**四层体检报告**（每层给问题数与最严重的 3 条）：

| 层 | 检查什么 |
|---|---|
| 结构 | 骨架章节是否齐全（对照《方案编写通用规范》结构条款：文档控制→建设总览→…→待确认→附录）；背景章是否"先问题后价值"；每章有无导读；待确认是否独立成章 |
| 内容 | 依据是否可溯源分类；方法与事实是否分离；每步有无交付物；责任是否到人；异常路径是否齐全；判定规则是否形式化 |
| 语言 | 跑 `scripts/term_scan.py`：生造词候选数、隐喻词命中、破折号数、绝对化断言数、行业歧义词 |
| 格式 | 是否需转正式交付格式（调用 word-deliverable 技能）；按《方案编写通用规范》附录 A 五组清单预估交付自检工作量 |

报告末尾给**轮次计划**（哪几轮需要、优先级、预估工作量），用户确认后开工；用户可以说"只跑第 3 轮"切专项模式。

## 第 1 轮：结构层

按《方案编写通用规范》结构要点逐项对照：补缺的骨架章（建设总览、待确认事项、验收）；背景章重组为"问题→价值"；每章加导读；清单/判定/映射表格化。产出章节级"调整对照表"（挪/并/删/增），用户确认后执行。

## 第 2 轮：内容层

按规范内容要点逐项对照：依据补分类标注（事实/行业惯例/双方约定/方案假定）；"须确认"与"方案假定"分离；每步补交付物与责任角色；异常/回退路径补齐；判定规则改"分档＋操作问法＋正反例"；KPI 补公式与基线。产出内容问题清单（P0/P1 编号），用户确认后逐项修。

## 第 3 轮：语言层

按下方"语言层五步"执行：扫描 → 对照表 → 批准 → 替换 → 三重验证。含页数压缩与判定去打分化。

## 第 4 轮：格式层

转正式 Word 交付版：调用工作区的 **word-deliverable** 技能（无该技能时按目标格式规范输出）。交付前自检按《方案编写通用规范》**附录 A 的五组清单**执行（清单唯一权威源，本文件不复述），输出逐项报告（通过/不通过/证据位置）。两项都通过才给"可交付"结论。

## 轮间纪律

见 SKILL.md 硬约束第 10-12 条：每轮小结由用户决定去留；上一轮已确认的结论下一轮不推翻；涉及口径结论的改动单独提请确认，不在语言轮夹带；每轮留痕（改前快照、对照表、验证输出）。

## 专项模式：语言层五步（第 3 轮的执行细则）

方法论母本：`references/去AI味与术语对齐操作指引.md`。以下为执行入口。

### 第 1 步：备料与快照

保留改前版本文件（快照不可省，硬约束 6）；确认语料目录清单；若是 docx，先提取纯文本工作副本。向用户声明本轮优化的范围（哪些层：造词/句式/通读/压缩）。

### 第 2 步：三层扫描 + 行业语境检查

- **造词层**：跑 `scripts/term_scan.py <目标文档> <语料目录>`，得到"文档高频＋语料零命中"的生造词候选、后缀造词（XX化/XX性/XX感）、隐喻词命中情况。
- **句式层**：term_scan.py 同时输出破折号清单与绝对化断言清单（"必然存在""多数源于"之类）。
- **行业语境层**：列出在目标行业中有另一含义的词（制造业的"生产"、金融的"清算"），逐个判断是否歧义。
- **通读层**：逐段人工通读，抓一次性 AI 味表述（模糊归因、夸大意义、机械排比）——这层不做机器扫，靠读。

### 第 3 步：对照表（用户确认门）

编对照表，模板：候选词｜文档位置与次数｜改后词｜语料出处｜保留或改判理由。**必须经用户逐条确认后才动正文**（硬约束 7）。替换词本身要过语料验证——不允许用一个自造词替换另一个自造词。有语料出处的行业词（工单、台账、评分卡等）列入保留清单，不误杀。

### 第 4 步：执行替换（脚本三重验证）

用 `scripts/fix_terms.py <pairs.json>` 执行（`--dry-run` 先断言）：pairs 来自批准后的对照表（file/old/new/expected，expected 取扫描实测次数）；脚本先全量断言再写回、组内长串先于短串。**替换必须在追加新修订历史行之前执行**（硬约束 8；历史行里的旧词会破坏计数断言）。随后用 `scripts/check_terms.py <check.json>` 验证：旧词零残留（`body_start` 排除修订历史区——旧版本描述保留当时的原名，属合法残留）、新词就位、结构不变。两脚本的完整用法与最小示例见 `examples/README.md`（端到端可跑）。

### 第 5 步：收尾复查

结构不变断言（check_terms.py 的 structure 项，或对源 spec 按块型统计）；页数核对，超预算走压缩三轮法：①结构层并删冗章 ②表格层重复段落改表 ③段落层删二次展开与铺垫；交付四件套（问题清单、对照表、验证报告、页数/结构核对结论）给用户。

## 判定去打分化改法（专项调用时）

打分制改勾选式——每档给"操作问法＋正反例"，删掉分数与权重，判定标准从"几分"变为"符合哪档"。

## 工具链（均已实跑验证，含端到端最小示例）

| 脚本 | 用途 |
|---|---|
| `scripts/term_scan.py` | 三层扫描：生造词候选（n-gram＋语料零命中＋组合词分流＋覆盖过滤）、隐喻词命中、破折号、绝对化断言、行业歧义词 |
| `scripts/fix_terms.py` | 替换执行：先全量断言（fail-fast）后写回，长串先于短串 |
| `scripts/check_terms.py` | 三重验证：ABSENT（排除修订历史区）/ PRESENT / 结构不变 |
| `examples/` | 端到端最小示例：示例稿＋语料＋pairs/check 配置＋README（scan→对照→fix→check 全链路演示） |
