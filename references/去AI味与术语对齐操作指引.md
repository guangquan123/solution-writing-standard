## 一、语料库

### 1.1 语料分级（替换词出处优先级）

| 级别 | 语料 | 用法 |
| --- | --- | --- |
| A | 委托方正式制度（管理办法、流程地图等） | 替换词首选；术语口径以它为准 |
| B | 项目前期商务文件 | 次选；商务口径 |
| C | 行业国标（GB/T、DCMM、DAMA） | 方法论术语出处 |
| D | 通用公文用语 | 兜底；确认不是自造词即可 |

商务敏感材料（合同、成本、报价类）**只读提取词频，不复制内容**进任何交付物。

### 1.2 命中率判定规则

- 拟用词在语料中出现 ≥1 次 = 有出处，可进对照表。
- 文档中重复出现（≥2 次）且语料零命中 = 生造词候选，必须处置（替换或给出保留理由）。
- 文档中仅出现 1 次且语料零命中 = 不进自动清单，留给通读层人工判断。教训：对低频词做自动 n-gram 扫描会产出千条级噪音候选（实测 1391 条），得不偿失。

## 二、五步流程

### 第一步 造词层扫描

1. 提取文档全文：markdown 直接读；docx 用 python-docx 提取段落＋表格文本。
2. n-gram 统计：2～6 字词组，保留出现 ≥2 次的。
3. 逐个候选查语料命中（`rg -c "词" 语料目录` 或脚本遍历）。
4. 附加扫描三类：
   - 后缀造词：XX化 / XX性 / XX感（语料命中的保留，如"权威性""符合性"）；
   - 隐喻词：引擎、抓手、载体、赋能、三角、底账、镜像、影子……以语料命中为准，不凭感觉；
   - 动词性生造：反哺、反挖、入台之类（语料零命中即改"反馈""识别""接入"等通用动词）。
5. 产出：候选词表（词｜文档次数｜语料命中数）。

### 第二步 句式层扫描

- 破折号"——"逐处列出：作解释连接的改冒号或改写为动词句（"A——即B" → "A，也就是B" / "A指B"）。
- 绝对化断言：必然 / 必然存在 / 多数源于 / 一定会 / 只需…即可 → 弱化为有据表述（常见原因是 / 通常会有 / 在…前提下）。
- 模糊归因：据说 / 普遍认为 / 业界共识 → 给出处或删除。
- 宣传腔与机械排比：全面提升、深度融合、赋能千行百业类 → 改直述。

### 第三步 对照表编制（用户确认门）

表格列：**候选词｜文档出现次数｜改后词｜改后词语料出处（文件＋次数）｜处置（替换／保留＋理由）**

- 保留清单单独成节：有语料出处的行业词不误杀（工单、评分卡、台账、五来源等方法论命名惯例）。
- 行业语境歧义专项：对主营业务词做交叉检查——制造类业务的"生产"＝制造，IT 义"生产告警／生产环境／生产阻断"必歧义，去前缀或改写；工程黑话（耦合、非功能、门禁等语料零命中词）改业务读者能懂的说法。
- **先交对照表，用户逐条批准后才执行**——这是规范七.1 施工总图纪律的术语版；替换词同样要过语料验证，不允许用一个自造词换掉另一个自造词。

### 第四步 替换执行（脚本模式）

- 长串先于短串，避免子串误伤；整句改写的精确句对先行，词级全量替换兜底。
- 每处替换带计数断言：替换前 `count(旧) == 预期`，替换后 `count(旧) == 0` 且 `count(新) == 预期`。
- Windows 注意：PowerShell 里 `python -c` 的引号转义易坏，替换逻辑一律写成临时 .py 文件执行。

### 第五步 三重验证＋通读

1. **旧词零残留**：全部旧词 ABSENT 检查，但排除修订历史区——文档控制表旧版本行里的旧术语是历史记录，合法保留（规范七.13）。
2. **新词就位**：PRESENT 检查（新术语在预期章节出现，含全称／简称两处）。
3. **结构不变**：块数统计前后一致（h1/h2/p/table/note 计数）；渲染后复查页数与空白页——修订历史表加行可能把后文推成空白页，压回后须复查全部分布。
4. 通读层人工复查：逐段通读抓一次性 AI 味表述（自动扫描只覆盖重复词，一次性的靠人眼）。

## 三、脚本骨架（示例，使用时按文档实际调整）

### 3.1 候选词扫描

```python
# scan_candidates.py —— n-gram(>=2次) + 语料命中
from collections import Counter
from docx import Document
from pathlib import Path

def docx_text(path):  # 段落+表格全文本
    d = Document(path)
    parts = [p.text for p in d.paragraphs]
    for t in d.tables:
        for r in t.rows:
            for c in r.cells: parts.append(c.text)
    return '\n'.join(parts)

text = docx_text('方案.docx')
ngrams = Counter(text[i:i+n] for n in (2,3,4,5,6) for i in range(len(text)-n))
corpus = ''.join(p.read_text(encoding='utf-8', errors='ignore')
                 for p in Path('语料目录').rglob('*.md'))  # 按实际扩展名调整
for w, cnt in ngrams.items():
    if cnt >= 2 and len(w) >= 3 and w not in corpus:
        print(cnt, w)   # 人工过筛：绝大多数是切词噪音，只留"像一个术语"的
```

### 3.2 替换执行

```python
# fix_terms.py —— PAIRS 驱动，逐条计数断言
PAIRS = [  # (旧, 新, 预期次数)  —— 预期次数来自第一步扫描，禁止拍脑袋填
    ("阻断门禁", "发布准入", 7),
    # ...
]
for path in ['part1.json', 'part2.json']:   # 或 .md 源文件
    s = open(path, encoding='utf-8').read()
    for old, new, exp in PAIRS:
        assert s.count(old) == exp, f"{path} {old}: {s.count(old)} != {exp}"
    for old, new, exp in PAIRS:
        s = s.replace(old, new)
    open(path, 'w', encoding='utf-8').write(s)
```

### 3.3 三重验证

```python
# check_content.py —— PRESENT/ABSENT/结构不变
PRESENT_BODY = ['发布准入', '数据质量技术规则登记表']  # 新词必须在正文出现
ABSENT_BODY  = ['阻断门禁', '规则说明卡']              # 旧词必须清零
# body 起点 = 导读页/正文第一章标记；文档控制表（含修订历史）不计入 ABSENT 区域
for kw in ABSENT_BODY:
    assert kw not in body, f'残留: {kw}'
for kw in PRESENT_BODY:
    assert kw in body, f'缺失: {kw}'
# 结构不变：替换前后 h1/h2/p/table 计数一致（对 json spec 按 type 统计）
```

> 脚本固化说明：3.1～3.3 已固化为配套脚本——`scripts/term_scan.py`（扫描：n-gram＋语料命中＋组合词分流＋覆盖过滤＋破折号/断言清单）、`scripts/fix_terms.py`（替换执行：先全量断言后写回、长串优先）、`scripts/check_terms.py`（三重验证：ABSENT 排除修订历史区／PRESENT／结构不变）。端到端最小示例见 `examples/README.md`。

## 四、常见误杀与保留参考

| 词 | 处置 | 理由 |
| --- | --- | --- |
| 工单、评分卡、台账 | 保留 | 数据治理语料常驻词 |
| 权威性、符合性、可信度 | 保留 | 语料在用（实测 9/13/4 次） |
| 闭环 | 保留 | 数据治理行业标准词，语料高频 |
| 5+2 判定、七步法 | 保留 | 项目方法论命名惯例 |
| 生产告警级／生产阻断级 | 改"告警级／阻断级" | 制造业业务语境歧义（四.11） |
| 耦合、非功能基线 | 改"衔接点""性能与运行基线" | 工程黑话，语料零命中 |
| 影子评价、治理三角 | 改"试点期评价口径""三个模块的分工" | 自造隐喻，语料零命中 |

## 五、纪律红线

1. 修订历史行是历史记录，不随术语改名而改；ABSENT 验证区域必须排除文档控制表。
2. 对照表未经用户逐条批准，不得执行替换。
3. 替换词无语料出处的，宁可保留原词并标注待确认，不得"顺手美化"。
4. 表达层清理不得触碰口径结论（规范六.12）；发现口径问题的，单独提请口径评审。
5. 证据留存：每轮优化的对照表、替换脚本、验证脚本与输出日志随文档版本归档（规范八.7 过程资产），供下轮复盘与审计。

## 六、页数压缩三轮法

超页时按顺序递进，每轮压完重新渲染数页，达标即停：

| 轮 | 层 | 手段 | 实测效果（49→43 页） |
| --- | --- | --- | --- |
| 1 | 结构层 | 删节/并节/挪附录；重复小节合并 | 主要减页来源 |
| 2 | 表格层 | 对照表段化（成对短列改连续段落）、字段合并（责任＋确认并一列） | 次要 |
| 3 | 段落层 | 合段、删二次展开（同一概念第二次解释） | 收尾 |

- **修订历史行数优先压**：多行合并为一行是零风险减行；反之，加行可能把后文推成空白页（实测：修订历史第 8 行溢出文档控制表 → 空白页 → 全章 +1 页），压回后必须复查全部分布。
- **微压缩无效阈值**：章末只剩十数行余量时，段落级微压缩不触发换页变化，需整章结构动作才减页。

## 七、判定去打分化改法

把打分制/阈值制判定改为勾选式或分层条件判定（规范五.13）：

- 0-2 分制七项准入 → ✓满足 / △部分满足 / ✗不满足 三档勾选（每档配操作问法）。
- "总分 ≥14 判定通过" → "5 条业务对象判定 + 2 条登记条件"分层：判定条件全满足才是候选，登记条件决定是否入目录。
- 打分制仅在必须量化排序时保留，且权重与阈值逐项可解释。
- 改法约束：判定形式变了但判定实质（准入标准）不变，属表达层；若实质标准要变，走口径评审，不在本指引范围内顺手带改。
