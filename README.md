# solution-writing-standard

把「方案怎么写、怎么改、交付前怎么查」固化成条款的 Skill：写方案时不必每次重新想结构、依据和检查项，照规范执行即可。

## 适合谁 / 不适合谁

| 适合 | 不适合 |
| --- | --- |
| 要提交评审、试点或验收的方案类文档：实施方案、建设方案、落地方案、标准规范说明 | 内部备忘、汇报材料、纯技术文档 |
| 想让 AI 写稿受统一规范约束，避免模板腔、AI 味和凭空编造 | 只想润色一段文字，不涉及文档结构与方法 |
| 有评审意见要逐条闭环，需要留修订痕迹与版本对照 | 需要业务判断、结论裁决、代签评审结论的场景 |

## 快速开始

第 1 步，把仓库内容放进 skills 目录：

```
<项目根>/.opencode/skills/solution-writing-standard/
```

第 2 步，直接说要做什么：

| 你要做什么 | 说一句 |
| --- | --- |
| 从零写方案 | 「帮我新写一份实施方案，先给我施工骨架和待确认清单」 |
| 按评审意见改稿 | 「这是评审意见（附件），先出施工总图给我确认，不要直接改正文」 |
| 术语与 AI 味清理 | 「方案要交了，把术语和 AI 味过一遍，先出对照表给我确认再改」 |
| 交付前过一遍清单 | 「方案要交付了，按规范把自检清单过一遍，给我逐项报告」 |

无脚本依赖，纯 Markdown，装完即可用，没有需要初始化的步骤。

## 你会得到什么

| 你的输入 | 走哪个模式 | 产出 |
| --- | --- | --- |
| 从零开始的方案需求 | A 新写 | 符合规范骨架与门禁的方案稿 + 文档控制表 + 待确认事项表 |
| 评审意见，或待修订的稿子 | B 改稿 | 改前快照 + 修订施工总图 + 逐处对照清单 + 升版后的定稿 + 修订留痕 |
| 一份接近交付的方案 | C 自检 | 逐项检查报告（通过 / 不通过 / 证据位置），35 项逐项过，不静默跳过 |

## 三种模式

| 模式 | 什么时候用 | 强制门禁 |
| --- | --- | --- |
| A 新写 | 从零起草 | 缺材料的步骤标注「待确认」，不允许臆造 |
| B 改稿 | 按评审意见修编 | 没有确认过的施工总图，不动正文；交付可直接粘贴的成品文字 |
| C 自检 | 交付前验收 | 程序化校验与视觉检查分开报告，两项都通过才给「可交付」 |

模式 B 的强制顺序，跳步即违规：留快照 → 施工总图 → 确认后动正文 → 逐处对照 → 留痕升版 → 抽检验证。

## 包含什么

| 文件 | 内容 | 什么时候必读 |
| --- | --- | --- |
| `SKILL.md` | 入口：三模式工作流与硬约束 | 始终 |
| `references/方案编写通用规范.md` | 规范全文：10 类条款 + 附录 A 自检清单 35 项 | 条款解释一律以它为准 |
| `references/去AI味与术语对齐操作指引.md` | 语料分级与命中率判定、五步清理流程、脚本骨架、误杀保留参考、三重验证、页数压缩三轮法、判定规则去打分化改法 | 涉及术语替换或 AI 味清理 |
| `templates/交付模板集.md` | 8 套骨架：文档控制表、本版变化表、施工总图、待确认事项表、角色 RACI、评审问题登记表、一页导读、术语表三列制 | 需要产出表格式交付物 |

## 硬约束

- 禁止虚构：依据、数据、责任人、修订记录、评审结论没有出处的一律不写，标「待确认」。
- 不承诺工期；能力未验证的只能写成「门禁 + 人工替代」，不写「已具备」。
- 口径修改（正式命名、分类结论）与通俗化翻译分两条线：翻译不动口径，口径变更走单独确认。
- 覆盖已有交付文件前必须先获确认，并保留改前版本。
- 只做编写、改稿与自检，不代签评审结论，不代使用者做业务判断。

## 边界

规范条款针对文档方法与流程，与具体业务领域无关；具体业务内容（名称、责任人、数据、系统配置）由执行方确认，不由本 Skill 假定。

## 版本与维护

当前版本 **v1.2.0**，以 `SKILL.md` 的 `metadata.version` 为准。

- **升版规则**（沿用《方案编写通用规范》八.3）：定义、边界、类型、责任发生影响兼容性变化时升主版本；补充说明或非语义调整时升次版本。
- **修订流程**（沿用规范七.1、七.9）：先出施工总图，确认后才动正文；任何一轮大改前先留改前快照，支持对比与回退。
- **版本号同改**：`metadata.version`、本文件与变更说明须同步修改，避免同一仓库出现多个版本号。
- **不设文档控制表**：本仓库是 Skill 源码而非交付文档，版本变化以 `metadata.version` 与提交历史为准；提交信息写明「改了什么」与「为什么改」。
- **内容边界**：条款只针对文档方法与流程，不承载具体业务内容、具体使用者信息与具体系统配置。
